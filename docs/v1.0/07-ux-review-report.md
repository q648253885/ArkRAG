# 人机交互合理性校验报告 v1.0

> 日期：2026-10-04 ｜ 站在首次使用 ArkWork + ArkRAG 的用户视角走查（学习成本/操作路径/文案/一致性/容错/防呆）

## 走查结论（按维度）

| 维度 | 结论 | 说明 |
|------|------|------|
| 学习成本 | ✅ 低 | 面板三 Tab 自解释；未连接时知识库页直接给"去配置"引导，首次配置 3 步完成（地址→测试→保存） |
| 操作路径 | ✅ 短 | 高频路径"建库→上传→检索"全部在单面板内完成，无页面跳转；Agent 侧零配置（装完插件工具自动可用） |
| 文案清晰度 | ✅ | 错误三层结构（现象+原因+动作）落实：如"无法连接 ArkRAG 服务（…）。请先启动：java -jar arkrag-server.jar，并检查连接设置里的服务地址" |
| 一致性 | ✅ | 成功=绿 toast、失败=红 toast、破坏性操作=确认弹窗，全面板一致；工具命名/错误提示与 MCP 侧同源 |
| 容错性 | ✅ | 网络 10s 级超时不悬挂；失败状态行保留原因；URL 失焦即时校验；空输入拦截 |
| 防呆 | ✅ | 删除 KB 强确认（文案列明后果+不可恢复）；同名覆盖有提示文案；20MB 面板上限有替代路径说明 |

## 缺陷（必须修）

无阻塞/严重项。

## 改进建议（列优先级，由用户决定是否排期）

| 优先级 | 建议 |
|--------|------|
| P1 | 摄入失败行加"重试"按钮（当前需重新上传同名文档触发覆盖，语义等价但不够直观） |
| P1 | token 保存后输入框仍明文可切换显示——已有显隐切换，建议默认隐藏状态记忆上次选择 |
| P2 | 知识库 Tab 在服务未配置 Embedding 时顶部加黄条提示（当前仅测试连接时发现） |
| P2 | 检索结果卡增加"复制"动作（写报告场景高频） |
| P2 | 面板 320px 极窄宽适配核查（dock 拖窄场景） |

## 最终总结

ArkRAG v1.0 的三条使用路径（ArkWork 插件 / MCP 直连 / HTTP API）在各自语境下自洽：插件面板覆盖了配置-管理-试用闭环，Agent 工具对模型暴露的描述可直接引导模型正确调用，MCP/HTTP 错误信息可读可行动。文档（README 快速开始 + 面板内提示）与实际行为一致，未发现"文档说有实际没有"的断层。
